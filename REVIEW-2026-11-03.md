# Code review – 2026-11-03

Scope: every playbook, role, inventory example, script and both hand-run kits (PuTTY, VS Code).
Covers both architect findings lists. Line numbers point at the **original** code (before these fixes).
Nothing here was run on a real box. See "Not verified without hardware" at the end.

**Boxes are not FIPS.** FIPS is now optional everywhere. `fips_required` defaults to false for Cleveland and Martinsburg (`platform_model: mpx9200`).
Every FIPS-only check is skipped unless `fips_required: true`, and they all still work if you turn it on (then use `mpx9200fips`).

## The config-loss bug (CRITICAL)
**mpx.yml:24-32 + roles/las_apply/tasks/main.yml:46-58,83-102.** When `las_apply` is on, the license step applies LAS. LAS warm-reboots the box,
and this happened before `mpx_save` ran. The reboot threw away everything not yet saved: hostname, NTP, DNS, RPC passwords and the HA pair.
The HA check had already passed before the reboot, so the play still ended green.
Under `serial: 2` it also rebooted both HA nodes at the same time.
**Fix:**
- Config is saved after the build steps and before licensing.
- `las_apply` saves again right before it applies.
- Licensing runs in its own play: `serial: 1`, `order: reverse_sorted` (the future secondary goes first).
- After the reboot, the play waits for the box and checks that the HA peer is back.
- A box that is already licensed is skipped, so a re-run does not reboot it again (`las_apply_force` overrides this).
